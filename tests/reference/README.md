# Independent reference-C vectors

`argon2-20190702.tsv` is generated by the unmodified reference implementation
[P-H-C/phc-winner-argon2, release 20190702](https://github.com/P-H-C/phc-winner-argon2/tree/62358ba2123abd17fccf2a108a301d4b52c01a7c),
commit `62358ba2123abd17fccf2a108a301d4b52c01a7c`. The generator links its
portable `src/ref.c`, BLAKE2b and other core C files with threading disabled.
Expected bytes do not come from this Rust implementation or its Verus model.
The pinned upstream source offers CC0 1.0 or Apache-2.0; see [NOTICE](../../NOTICE).

## Corpus

The 168 rows cover all three algorithms, both `0x10` and `0x13`, seven tag
lengths (4, 16, 32, 63, 64, 65, 96), and these four configurations:

| Lanes | Requested KiB | Passes | Password bytes | Secret bytes | AD bytes |
|---|---|---|---|---|---|
| 1 | 8 | 1 | 0 | 0 | 0 |
| 2 | 67 | 3 | 32 | 8 | 12 |
| 3 | 100 | 2 | 300 | 0 | 0 |
| 4 | 256 | 2 | 32 | 8 | 12 |

Password bytes are `0x01`, the 16 salt bytes are `0x02`, secret bytes are
`0x03`, and associated-data bytes are `0x04`. These are public test inputs,
not deployment recommendations. Requested memory is deliberately unrounded
in two cases. Tag lengths straddle BLAKE2b/H-prime boundaries.

Rows are whitespace-separated: algorithm number, decimal version, lanes,
requested KiB, passes, password length, secret length, AD length, hex tag.
The Rust test runs each row against scalar and every locally available SIMD
backend. Ordinary `cargo test` reads the fixture and needs no C compiler,
network access or additional Rust dependencies.

## Reproduce

Prerequisites: Git, a POSIX shell and a C99 compiler (`cc`, or the executable
named by `CC`). From the Rust crate root:

```sh
git clone --branch 20190702 --depth 1 \
  https://github.com/P-H-C/phc-winner-argon2.git target/reference-argon2-20190702
sh tools/reference-vectors.sh target/reference-argon2-20190702 \
  > target/reference-vectors.tsv
diff -u tests/reference/argon2-20190702.tsv target/reference-vectors.tsv
cargo test --locked --release --test reference_vectors
```

The [script](../../tools/reference-vectors.sh) checks the exact commit and
rejects modified reference source/header files, then compiles the
[generator](../../tools/reference_vectors.c). It uses a temporary executable
and removes it on exit. It does not update the checked-in fixture.
CI separately regenerates and compares the fixture. Regeneration is a review
step: never update expected outputs merely because the Rust test disagrees.

This deterministic corpus is not differential fuzzing, exhaustive coverage,
an independent security audit, or proof of the reference implementation.
